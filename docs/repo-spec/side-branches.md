# 孤立的并行分支：职责与命名约定

本文规定本组织各仓库中与 `main` 完全无公共祖先的那些分支——本文称**孤立的并行分支**（简称并行分支）——的职责划分与命名规则。新增并行分支必须先改本文，再建分支。

## 一、术语

| 术语 | 含义 |
|:---:|:---|
| 主干 | 仓库的 `main` 分支，放源码、配置与开发期依赖的材料 |
| 孤立的并行分支 | 与 `main` 完全无公共祖先的分支，只承载某一类数据，不从主干派生，也不合并回主干 |
| 并行分支工作区 | 并行分支在本地以 `single-branch/<分支名>/` 目录存放，自带 `.git`，是一个独立的仓库工作区 |

这类分支与主干的关系只有一条：两者同属一个远端仓库，但历史互不相交。社区没有统一叫法，本组织统称它们为孤立的并行分支，暂不做细分。

## 二、通用规则

| 规则 | 说明 |
|:---:|:---|
| 无公共祖先 | 用 `git checkout --orphan <名字>` 建立，首提交只放一个 `README.md`，说明本分支的职责 |
| 不从主干派生 | 并行分支里不出现主干的源码、构建脚本与依赖清单，需要脚本时另行约定 |
| 不合并回主干 | 并行分支的内容不进主干历史；需要消费时由 CI 读取或复制，不做 merge |
| 只由 CI 写入 | 人工只在建立分支与排查时提交；日常写入由流水线完成 |
| 本地存放 | 在 `single-branch/<分支名>/` 检出为独立工作区，主仓库忽略该目录 |
| 不自动创建 | 流水线发现并行分支缺失时报错中止，不代为创建，避免出现空壳分支 |
| 发布方式 | 需要进 Pages 的并行分支，在流水线最后阶段把内容复制合并进一个页面包，再统一上传部署 |

## 三、职责与命名

| 分支名 | 职责 | 放什么 | 进 Pages | 谁读 |
|:---:|:---|:---|:---:|:---|
| `dist-history` | 产物旧版留存，保证历史版本的产物随新版一同发布 | 每次发布的产物副本，按版本号分目录，只保留最近若干个 | 是（与主干产物合并成包） | 页面自身、需要回退到旧版的用户 |
| `certs` | 存放可公开的证书与公钥 | 根证书、各来源的终端签名证书与公钥；不含私钥，不含合集内作者公钥 | 是 | 网页与合集在运行时取锚点与验证材料 |
| `trusted-manifest` | 存放信任列表 | 信任清单及其索引所需的派生数据，例如各来源证书的路径与根证书指向 | 是 | 网页与合集在启动时读取可信来源 |
| `ci-memory` | 给流水线恢复记忆 | 跨构建需要延续的状态；分支内按**功用**分扁平文件夹，名字用短横线连接，不再往下分层 | 否 | 只有流水线 |

命名规则：

1. 名字说明用途，不说明形态；不要用 `data`、`online`、`store` 这类笼统词。
2. 用短横线连接小写单词；不加仓库名前缀（并行分支属于仓库自己，不需要自报家门）。
3. 新增职责必须新开名字，不把两类内容塞进一个并行分支。
4. 一个新名字启用后，不得再被赋予第二种含义。

## 四、与主干 `certs/` 的区别

主干里也有 `certs/` 目录，两者职责不同，不要混用：

| 位置 | 用途 | 谁使用 |
|:---:|:---|:---|
| 主干 `certs/` | 构建期依赖的材料，例如把根证书内嵌进产物 | 构建脚本 |
| 并行分支 `certs` | 对外发布的材料，供网页与合集在运行时取用 | 页面与合集的运行时 |

## 五、当前使用情况

| 仓库 | 并行分支 | 说明 |
|:---:|:---:|:---|
| `DeepSeek-Chat-Enhanced` | `dist-history`、`certs`、`trusted-manifest` | 三份内容分别归档，发布时合并成页面包 |
| `awesome-dsc-plugin` | `ci-memory` | 记三层清单的上一版，放在 `layer-manifests/` 下按分发路径镜像 |
| `dsc-inner-plugin` | 无 | 只发布 Pages 制品，不跨构建延续状态 |
| 其余仓库 | 无 | 见各仓库 `docs/README.md` |

## 六、ci-memory 的内部结构

分支内每个文件夹对应一种需要跨构建延续的状态，名字直接说明它存什么，用短横线连接，不再往下分层；需要按路径组织的状态（例如分层清单）按其天然路径镜像，不算额外分类。

| 文件夹 | 存什么 | 谁写 | 谁读 |
|:---:|:---|:---:|:---:|
| `layer-manifests/` | 三层清单（合集根、作者目录、插件目录）的上一版 `manifest.json` 与 `manifest.json.sig`，按与分发目录相同的路径镜像 | 流水线 | 流水线，用于沿用 `revision` |

新增文件夹时在本表登记，并写清写者与读者。

## 七、归档 tag 的命名

并行分支上的归档 tag 用「发行 tag + 短横线 + 分支名」命名，例如 `dsc-1.0.0-dist-history`、`dsc-1.0.0-certs`、`dsc-1.0.0-trusted-manifest`。tag 后缀与分支名保持一致，不做另一套缩写。

## 八、扩展流程

1. 在本文第三节新增一行，写清职责、内容、是否进 Pages、谁读。
2. 在第五节登记使用该并行分支的仓库，并说明放哪份内容。
3. 用 `git checkout --orphan` 建立分支，首提交只放 `README.md`。
4. 在 `single-branch/<分支名>/` 检出工作区，并确认该目录已在主仓库忽略。
5. 更新流水线、脚本与文档里的分支名引用；改名与建分支要在同一次提交里完成。
