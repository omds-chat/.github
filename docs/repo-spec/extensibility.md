# 扩展的两条时间线：开发期与运行期

本文把本组织各仓库里出现的「可扩展」分成两类，并逐项说明每个东西属于哪一类。判断只需要问一句：**要不要重新构建产物。**

## 一、两类扩展

| 类别 | 定义 | 谁来做 | 判定 |
|:---:|:---|:---:|:---|
| 开发期扩展 | 在构建之前改动源码、配置、Schema 或内嵌材料，改完必须重新构建产物 | 开发者 | 需要重新构建才生效 |
| 运行期扩展 | 产物不变，用户在使用现场加载新的插件、资产、来源或数据 | 产品用户 | 不重新构建就生效 |

同一样东西可以只属于一类，也可以同时有两层。把两层混为一谈，就会出现「用户以为能自己加，实际要发版」或者「开发者以为要发版，实际用户可以自己加」这类误解。

## 二、逐项归类

| 东西 | 类别 | 说明 |
|:---:|:---:|:---|
| `DeepSeek-Chat-Enhanced` 的插件体系 | 运行期扩展 | 产物的插件列表可以由用户增删；插件从地址或本地包装入，卸载即移除，不重新构建 |
| `DeepSeek-Chat-Enhanced` 的能力集合（`capabilities`） | 开发期扩展 | 新增一项能力要改 core 与引擎、要升版本、要重新构建；插件在运行时不能申请到集合外的能力 |
| `DeepSeek-Chat-Enhanced` 的挂载点集合（`mounts`） | 开发期扩展 | 宿主在哪些时刻回调插件，由宿主决定；插件只能在既有挂载点上声明 |
| `DeepSeek-Chat-Enhanced` 的 `certs/` 目录 | 开发期可变更、运行时**部分内嵌** | 根证书与网页 EEC 在构建时被内嵌进产物（`__ROOT_CA_PEM__`、`__PAGES_EEC_PEM__`），换了必须重新构建；其余来源的证书不由产物携带，运行时从 `certs` 分支取，换证书不需要重建产物 |
| 页面版本继承（`application-version`） | 运行期 | 页面自行比对版本并提示刷新或跳旧版，不涉及构建 |
| `dsc-provider-switch` 的来源（provider 描述） | 运行期扩展 | 用户可以在插件界面里增删来源，产物不变 |
| `dsc-provider-switch` 的兼容格式（DeepSeek / OpenAI / Anthropic）与能力标识 | 开发期扩展 | 新增一种格式或一项能力要改 core 与插件、重新构建；用户不能在运行时扩展格式集合 |
| `dsc-provider-switch` 的名称与描述 Schema | 开发期扩展 | Schema 随版本发布，改动要重新构建并升级版本 |
| `dsc-humanize` 插件本体 | 运行期扩展（对 dsce 而言） | 它是 dsce 插件体系里的一个插件，用户可装可卸 |
| `dsc-humanize` 的资产包 | 运行期扩展（对它自己而言） | 资产包由用户导入、从合集安装，产物不变；新增资产类型属于它的开发期扩展（与插件版本同步） |
| `dsc-humanize` 的资产类型集合 | 开发期扩展 | 与插件流程环节绑定；改集合等于改插件版本 |
| 合集（`awesome-dsc-plugin`、`dsc-inner-plugin`、两个资产合集）的收录内容 | 运行期扩展 | 作者提交、CI 收录，产物重新生成但站点代码不变 |
| 合集的三层清单与 `ci-memory` | 运行期 | 由流水线读写，不是用户操作 |
| 模板仓库的骨架内容 | 开发期 | 复制骨架是开发动作，不是运行期扩展 |
| `public/certs` 与信任清单 | 开发期可变更、运行时分发 | 证书变了不需要重新构建网页，因为产物只内嵌根证书与网页 EEC；其余由运行时按分支取 |

## 三、几条容易混的边界

1. **「插件运行时能加」不等于「能力能加」**：插件可以随时安装，但插件能使用的能力集合是宿主的开发期决定。
2. **`dsc-humanize` 有两层扩展**：对 dsce 它是运行期可装的插件；对它自己，资产包是运行期可导入的内容，资产类型是开发期决定。
3. **证书分两半**：内嵌的那两份（根证书、网页 EEC）换了必须重建；分支上分发的那部分换了只影响运行时取用。
4. **模板不是扩展点**：模板是开发者复制的起点，产出的仓库才可能带运行期扩展。

## 四、写新设计时的自检

| 问题 | 用途 |
|:---:|:---|
| 这个新增项要不要重新构建产物？ | 要 → 开发期；不要 → 运行期 |
| 用户能不能在不发版的情况下新增一项？ | 能 → 必须为它设计运行期入口与界面 |
| 这东西变了以后，已安装的用户会不会静默失效？ | 会 → 需要版本兼容或迁移口径 |
| 它属于哪个仓库？ | 开发期改动落在该仓库源码；运行期入口落在产品界面 |
