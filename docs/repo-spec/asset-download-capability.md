# assets:download 能力与受信来源插件层级

本文规定「引擎代取大体积资产」这项能力（标识 `assets:download`）的语义、申请条件，以及它依赖的新增层级**受信来源插件**。它是一项按来源分级开放的能力：在此之前，能力要么对全部插件开放，要么只对内置插件开放，没有中间档。因此新增层级、改动申请条件或改动清单字段，都必须先改本文，再实现。

本文与各仓库自身文档冲突时，以各仓库文档为准。`assets:read` 的既有口径见 `DeepSeek-Chat-Enhanced` 的 `src/components/dsc-plugin-engine/README.md` 与 `src/components/dsc-core/assets.ts`；新增能力属于开发期扩展，见 [extensibility.md](extensibility.md)。

## 一、是什么

### 1.1 能力语义

`assets:download` 是单动作能力：插件在清单里声明一个不可变的资产地址与它的 SHA-512，引擎负责取回、校验，并把结果与进度交给用户与插件。

| 项目 | 规定 |
|:---:|:---:|
| 发起方 | 插件调用上下文成员并传入资产标识；地址与哈希来自插件清单，不由调用参数决定 |
| 取件方 | 引擎（`dsc-core` 提供唯一实现），插件不接触请求、重定向与响应流 |
| 校验 | 引擎按清单声明的 SHA-512 与字节数校验，不通过不交付 |
| 交付 | 校验通过的字节交给插件，插件自行写入 IndexedDB 等本地存储 |
| 进度与取消 | 由引擎在界面上显示，用户可随时取消；取消即中止请求 |
| 用户提示 | 每一次下载事件都提示，不去重、不按来源合并 |

「每一次」指每一次实际发生的传输：同一插件对同一资产的再次下载、缓存未命中的重下、用户取消后的重试，都各自提示一次。

### 1.2 与 assets:read 的分工

两条能力都由引擎实现、都不带凭证、都只接受 https 与回环 http，区别只在「取什么、取多大、能不能留下来」。

| 维度 | `assets:read` | `assets:download` |
|:---:|:---:|:---:|
| 面向内容 | 小体积文本与小型二进制（清单、证书、JSON、小图） | 大体积二进制（模型权重、字库、音色包等） |
| 体积 | 单次响应体上限 512KB，超限中止 | 按清单声明的字节数核对，不按固定上限截断 |
| 结果形态 | 三态原样返回（内容 / 状态码 / 无状态码），由插件解释 | 只有两种：校验通过的字节，或明确失败（含哈希不匹配与取消） |
| 留存 | 引擎不落盘，插件拿到即用 | 引擎不落盘，插件自行落本地存储 |
| 限流 | 20 次 / 10 秒 | 按传输次数与总流量分别计，上限见 4.5 |
| 信任门槛 | 全部插件 | 仅受信来源插件（见 1.3） |
| 用户提示 | 首次访问某个来源地址提示一次，之后静默 | 每次下载事件都提示 |

判据一句话：能用 `assets:read` 取到、并且不打算长期留存的，就不要用 `assets:download`。

### 1.3 受信来源插件

「受信来源插件」不是一种新的签名材料，而是对「插件清单已被既有 PKI 覆盖」这一事实的称呼。它只有两个入口：

| 来源 | 认定依据 | 覆盖到插件清单的是 |
|:---:|:---:|:---:|
| 内部插件合集 `dsc-inner-plugin` | 整站 CMS 签名与 `dist/eec.pem`，市场先验整站再验作者签名 | 整站签名覆盖 `dist/` 内每一份文件，含各版本 `meta.json` |
| 社区插件合集 `awesome-dsc-plugin` | 合集 EEC 签三层清单 | 第二层清单覆盖作者公钥与插件清单 |
| 未收录的第三方插件 | 无 | 无 |

展示侧的「背书」与「可信」两档都属受信来源，但都要求本地来源结论为已确认；判定只问「这份插件清单是不是随受信合集发布的」，不看插件 id、不看作者是否知名。本地安装与自建来源的插件一律不在该层级内：它们的清单没有合集签名可验，内容与已收录版本相同也不因此获得资格。

## 二、为什么

### 2.1 为什么必须由引擎代取

- 插件不得自建通道：既有口径是插件对外取数只走宿主能力，同源直接调用全局 `fetch` 属于不合规。大体积下载若允许插件自己发，等于给每个插件发一张无上限的联网许可证。
- 凭证与配额不能交给插件：请求头、Cookie、重定向、并发与总流量都必须在宿主侧统一落实。交给插件，限流表与「不带凭证」的承诺会同时失效。
- 用户需要统一的进度与取消：取消必须真正中止底层请求，只有持有请求的一方才能做到；插件发起的传输，宿主界面上的按钮点不动。
- 大文件必须流式读：边读边累计摘要与字节数，超限或取消时立刻放手，这需要一个能读响应流、能中途放弃的执行者。

### 2.2 为什么信任层级只开到「被收录的插件」

- 收录是唯一可机检的背书：内部插件由组织自研并整站签名，社区插件由合集 EEC 与三层清单负责，两者都能回答「这份清单出自哪次发布、由谁签的」。
- 未收录的插件没有任何材料能回答同一个问题。能力一旦开放，等于让任意地址上的任意字节在用户设备上长期驻留，事后无法追溯来源。
- 与既有分层同构：`net:fetch` 只给内置插件，`assets:read` 给全部插件，本能力落在中间——比通用联网窄（只能取清单里声明过的地址与哈希），比只读文本宽（体积与留存都更大）。
- 层级只承诺出处，不承诺安全：收录不等于认证，这一层保证「地址与哈希来自一次可追溯的发布」，不保证资产内容无害，也不保证作者持续维护。

### 2.3 为什么哈希钉在清单里就够

- 清单已被 PKI 覆盖：内部合集是整站签名，社区合集是三层清单，`assets` 块与被签字节同处一份文件，改一个字就破签。
- 地址与哈希同处一处：改地址必改哈希（否则校验失败），改哈希必破签，两者无法分开替换。清单之外不另存一份地址表，也就不存在第二处可被单独改写的真相。
- 不新增机制：不需要新证书、新签名文件、新清单层，也不需要在下载时联网获取信任材料。模型与资产的完整性继承既有信任。
- 与既有做法一致：资产市场的整包安装本来就逐文件比对 SHA-512，这里只是把同一形状钉进插件清单，算法与写法都不变。

### 2.4 为什么每次都要提示

- 量级不同：`assets:read` 单次上限 512KB，提示一次足够；一次下载可能是几十到几百 MB，占流量、占磁盘，而且会长期留在本机。
- 提示是用户唯一的现场入口：哪个插件、哪个资产、声明多大、已收多少、能不能取消。没有这条提示，下载对用户是不可见事件。
- 提示不是审批：它不阻塞调用，不提供「允许一次 / 永久允许」这类选择；用户取消就是中止本次传输，下次仍会重新提示。
- 所以不做来源去重。`assets:read` 的首次提示按「插件 + 来源」去重，两条能力的提示语义不同是有意为之，不要为了统一而合并。

## 三、怎么办

### 3.1 申请与认定流程

| 步骤 | 谁做 | 做什么 | 不满足时 |
|:---:|:---:|:---:|:---:|
| 一、收录 | 合集 | 审核插件清单：地址协议、哈希形状、字节数与标识唯一性 | 预检与 CI 中止，不发布 |
| 二、发布 | 合集流水线 | 清单随合集签名（内部整站签、社区第二层清单） | 无签名即不构成受信来源 |
| 三、安装 | 引擎 | 校验来源；来源结论为「已确认」且来源是受信合集时授予能力 | 按 `unknown-capability` 拒绝，与不存在的能力不可区分 |
| 四、调用 | 引擎 | 按清单查资产标识，复核能力后再发起下载 | 抛 `PluginAssetError`，不发起任何请求 |

认定结果不回写清单，也不新增安装字段：授予在安装阶段判定，调用阶段再复核一次，与 `net:fetch` 的双重校验同形。清单申请了 `assets:download` 却没有 `assets` 块，或调用时传入的标识不在块内，按不合格清单处理。

### 3.2 清单字段形状草案

```json
{
  "id": "dsc-example",
  "capabilities": ["assets:download"],
  "assets": [
    {
      "id": "embed-model",
      "url": "https://example.org/assets/embed-model-1.0.0.onnx",
      "sha512": "128 位小写十六进制",
      "bytes": 184320000,
      "version": "1.0.0"
    }
  ]
}
```

| 字段 | 类型 | 规定 |
|:---:|:---:|:---:|
| `id` | 字符串 | 插件内唯一，小写字母开头，只含小写字母、数字与连字符；调用时用它指定资产 |
| `url` | 字符串 | 绝对地址，只允许 https；回环 http 仅供本地联调；不携带内嵌凭证与一次性签名参数 |
| `sha512` | 字符串 | 128 位小写十六进制，不带前缀；与资产市场逐文件比对的写法一致 |
| `bytes` | 整数 | 声明体积，用于进度总量与提前拒绝；实际字节数与声明不符即失败 |
| `version` | 字符串 | 三段数字；同一 `id` 换版本必须换地址或换哈希，不允许原地覆盖 |

`assets` 块只在申请了 `assets:download` 时出现；`id` 不得重复；首版按声明顺序串行取件（并发见 4.5）。

### 3.3 引擎侧行为

| 环节 | 行为 |
|:---:|:---:|
| 提示 | 每次传输前用气泡通知与悬浮卡片说明插件、资产、声明体积与来源地址；不用原生确认框，不用模态遮罩，不阻塞调用 |
| 请求 | GET，不带 Cookie 与自定义请求头，https（回环可 http）；清单以外的地址不会交给网络层 |
| 流式读取 | 边读边累计字节数与 SHA-512，不把整份内容先读进内存再校验 |
| 校验 | 摘要与字节数都与清单一致才交付；任一不符即失败，已读字节丢弃 |
| 失败 | 抛 `PluginAssetError`，`reason` 取 `protocol`、`status`、`timeout`、`too-large`、`hash-mismatch`、`aborted` 之一；除取消外只写插件日志 |
| 取消 | 用户点取消即 `AbortController.abort()`，请求真正中止，`aborted` 交给调用方，引擎不重试 |
| 进度 | 悬浮卡片显示已收字节与声明体积，完成后自动收起；同一插件同一时刻只显示一张卡片，多资产复用 |
| 合并 | 同一 `id` 与 `sha512` 的并发请求合并为一次传输，其余等待同一结果 |
| 缓存 | 第一阶段不落盘、不设持久缓存；交付后内存中的字节即可释放 |

### 3.4 插件侧职责

| 职责 | 规定 |
|:---:|:---:|
| 自存 | 校验通过的字节由插件写入 IndexedDB 或等价本地存储，键用 `sha512` |
| 命中即不下载 | 启动时先按 `sha512` 查本地副本，命中直接使用，不调用能力、不产生提示 |
| 版本替换 | `version` 变化或本地摘要不符时按新清单重新下载，旧副本删除 |
| 失败回落 | 下载失败、校验失败或用户取消，插件必须给出可用的降级路径（小模型、精简功能或明示不可用），不得让功能静默失效 |
| 配额 | `QuotaExceededError` 由插件处理（清理旧副本并提示），引擎不代管插件存储 |
| 卸载清理 | 停用或卸载时删除自己写入的副本，不留孤儿数据 |
| 不自建通道 | 不得为绕过本能力直连地址，也不得把地址转交其他插件代取 |

## 四、边界与未定项

### 4.1 模型选型与体积

本文不指定模型、推理精度与运行时。体积上限暂不写成固定数字：第一阶段由引擎按可配置上限拒绝超大资产，数值等第一个消费者出现后按实测确定（见 4.5）。选型是插件与资产作者的决定，引擎只保证「声明多大就取多大，取到的就是声明的那份」。

### 4.2 ort-wasm 不进下载通道

`onnxruntime-web` 的 wasm 与 js 胶水是运行时依赖，由宿主静态打包进产物，不走 `assets:download`，也不出现在插件清单的 `assets` 块里。理由：它是代码不是数据，加载时机在页面启动、体积固定、必须与宿主版本对齐；放进下载通道会让「资产」与「运行时」两个概念混在一起，并让离线可用性依赖首次下载成功。模型权重属于数据，按本能力取。

### 4.3 隐私模式下的降级

无痕窗口里 IndexedDB 可能不可用，或关闭即清空。降级口径：下载照常进行，插件按「无持久缓存」运行——每次需要时重新下载、每次都要提示；不得因写不进存储就拒绝工作，也不得把大体积内容挂在内存里长期占用。

### 4.4 第二阶段的触发条件

引擎托管模型注册表只在一个条件下启动：出现第二个消费者，即两个以上插件要用同一份权重，或同一份权重要在多个插件之间共享缓存。在此之前只做第一阶段。第二阶段要做的是按 `sha512` 内容寻址的共享缓存、跨插件复用、下载与缓存状态进设置页、离线可用性判定；第一阶段的设计不得阻碍它，例如不要在清单里写死只属于某个插件的缓存路径。

### 4.5 未定项

| 项目 | 现状 | 待定 |
|:---:|:---:|:---:|
| 单资产体积上限 | 引擎按可配置上限拒绝，数值未定 | 等真实模型体积与用户磁盘现实 |
| 限流数值 | 与 `assets:read` 分开计数，数值未定 | 等第一个消费者出现后按实测调 |
| 并发 | 首版按清单顺序串行 | 多资产并行与并发上限 |
| 断点续传 | 不做，取消即从头再来 | 大体积普及后再议 |
| 重定向 | 跳转后地址仍需 https，且不跨主机 | 跨主机 CDN 的现实需求 |
| 文案键名 | 复用宿主 `i18n`，插件不自行拼接文案 | 实现时随引擎文案表登记 |

本文是这项能力与这个层级的唯一权威文字：新增或调整层级、申请条件、`assets` 字段与引擎行为，都先改本文，再改 Schema 与实现。
